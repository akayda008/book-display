## 2026-09-01 — Sub-project 1: Corrective round 3
- **Milestone/cycle**: Sub-project 1 (Rich text formatting) — third, expected-final corrective round.
- **What was done**:
  - **Finished the binary-search consolidation.** `findMaxWordsThatFit` (paragraph word-count fitting) was the same binary-search shape as `findMaxItemsThatFit` (list/blockquote/lineblock item fitting), just with a different candidate builder. `findMaxWordsThatFit` is now a one-line wrapper that calls `findMaxItemsThatFit` with a closure over `renderParagraph`/`align` — no behavior change, confirmed by the browser walkthrough below.
  - **Closed the SSR sanitization gap in `renderInline()`.** Its `typeof window === "undefined"` branch previously returned marked's raw HTML unsanitized (unreachable today — `parseChapterBlocks` is only ever invoked client-side from `Book.tsx` — but a landmine if that ever changed). DOMPurify needs a real DOM, and adding `jsdom` as a dependency just to run it server-side against a currently-dead path seemed like more weight than the problem warranted (Engineering Principle 1: survey before building custom, but also don't add a dependency without weighing it). Instead, the server-side branch now strips all HTML tags via regex and re-escapes the remaining text — no code path through `renderInline()` can return unsanitized markup, in any environment, without needing jsdom. Documented the reasoning in a code comment since it's a real trade-off call, not an obvious default.
- **Verified**:
  - `npm run build` and `npx eslint .` both pass clean.
  - Browser walkthrough (temporary Playwright script, removed after): no console errors/warnings; paragraph splitting (including the bold/italic mid-page split) renders identically to before the consolidation.
  - Isolated Node-side test of the SSR fallback: fed `renderInlineServer()` an `<img src=x onerror=alert(1)> **bold** and *italic* text` string; output was `bold and italic text` — no tags, no `onerror`, confirming the fallback is safe by construction rather than relying on DOMPurify being reachable.
- **What's left**: Nothing outstanding. Per the reviewing session's note, the pre-existing Next-Page button disable-condition bug (flagged in round 1) remains untouched — confirmed still present, still out of this milestone's scope.

## 2026-09-01 — Sub-project 1: Corrective round 2
- **Milestone/cycle**: Sub-project 1 (Rich text formatting) — second corrective round after a closer re-review of `src/utils/pagination.ts`.
- **What was done**:
  - **Sanitize upstream, once.** `renderInline()` in `src/utils/markdown.ts` now calls `DOMPurify.sanitize()` on `marked.parseInline()`'s output immediately (guarded by `typeof window === "undefined"`, matching the existing SSR-safety pattern). This is the single point where raw, unescaped HTML enters a `Block` (headings, list items, blockquote lines, poem lines) — paragraph text was already safe via the `escapeHtml`/`wordsToHtml` word-tokenizer path, which only ever emits a fixed set of trusted tags. Since both the pagination measurement clone (`pagination.ts`'s `fits()`, via `.innerHTML =`) and the final display (`Book.tsx`'s `dangerouslySetInnerHTML`) consume the exact same `Block`-derived HTML string per ADR-002, sanitizing once at the source covers both. Removed the now-redundant second sanitize call and its `sanitize()` wrapper/`DOMPurify` import from `Book.tsx` — `page.html` is safe by the time it reaches there.
  - **Skip item-less atomic blocks instead of rendering an empty container.** `markdown.ts`'s blockquote parser drops blank `>` lines (`if (content) lines.push(...)`), so an all-blank blockquote reaches `fitAtomicItemsBlock` with `lines: []`. Added a guard at the top of `fitAtomicItemsBlock` in `pagination.ts`: an empty `items` array returns immediately with `remainingBlocks: null` (i.e. "nothing to add, move on") rather than calling `render()` on an empty array, which previously produced a styled-but-empty `<blockquote>`/`<ul>`/`<div class="line-block">`. Confirmed (by tracing the parsers) that list and lineblock can't structurally produce an empty items/lines array — every match into their while-loops unconditionally pushes at least one item — but the guard applies uniformly to all three call sites since it's a correct invariant regardless.
- **Verified**:
  - `npm run build` and `npx eslint .` both pass clean.
  - Sanitization: temporarily added `- <img src="x" onerror="window.__xssFired = true">Sanitization smoke test item.` as a list item, loaded the app, clicked through to that page, and confirmed via `page.evaluate` that `window.__xssFired` was never set to `true` and the rendered `innerHTML` (checked on both the visible page content and would apply identically to the measurement clone, since they share the same sanitized string) contained no `onerror` attribute — the `<img>` tag itself survived (DOMPurify's default config allows the tag, strips only the dangerous attribute), confirming sanitization is real, not accidentally stripping all content. Reverted the temporary test line after confirming.
  - Empty-block guard: temporarily added an all-blank blockquote (`>` / `>` / `>` with no text) between two marker paragraphs in the test-blockquote chapter, confirmed via captured HTML that the "before" and "after" paragraphs render directly adjacent with no `<blockquote>` element between them. Reverted the temporary addition after confirming.
- **What's left**: Nothing outstanding from this round.

## 2026-09-01 — Sub-project 1: Rich text formatting
- **Milestone/cycle**: Sub-project 1 (Rich text formatting) — rewrite the pagination engine to parse and fit markdown instead of plain text, per `docs/1 - Project Context/Roadmap.md`'s Current Milestone.
- **What was done**:
  - Added `marked` (markdown parsing) and `dompurify` (sanitization) as dependencies, per ADR-002.
  - New `src/utils/markdown.ts`: custom block-level parser (`parseChapterBlocks`) producing `heading` / `paragraph` / `list` / `blockquote` / `lineblock` blocks from a chapter's raw markdown, each tagged with an `Align`. Handles a `::: center|right|left|justify` fenced-block pre-processing pass (stack-based, warns via `console.warn` on an unclosed fence), a `|`-prefixed poem line-block pass (leading-space count becomes `padding-left` in `ch` units), and one heading level (`##`). Inline bold/italic is tokenized via `marked.Lexer.lexInline` into `FormattedWord[]` (`parseInlineToWords`) and reassembled via `wordsToHtml`, which closes/reopens `<strong>`/`<em>` spans cleanly at arbitrary word-count boundaries — this is what makes word-level splitting format-aware. Also added `checkDuplicateSlugs`, a stateless dev-time duplicate-slug warning.
  - Rewrote `src/utils/pagination.ts`: `fitContentIntoPage` now operates over `Block[]` instead of paragraph strings. Headings are atomic (whole-block fit-or-move). Paragraphs use the pre-existing whole-then-binary-search strategy, now via `findMaxWordsThatFit` over `FormattedWord[]`. Lists/blockquotes/line-blocks use a new `findMaxItemsThatFit` that binary-searches item count (not words) so the block can break at item/line boundaries without ever truncating inside one. Removed the dead, commented-out `paginateByHeight` function (`docs/5 - Project Maintenance/Technical Debts.md` item). `PaginationState.remainingParagraphs: string[]` became `remainingBlocks: Block[]`.
  - `src/components/Book.tsx`: measurement clone and both page divs changed from `.textContent`/`whitespace-pre-line` `<p>` to `innerHTML`/`dangerouslySetInnerHTML` on `<div>`s (a `<p>` can't legally contain block children like `<h3>`/`<ul>`/`<blockquote>`). Added a `sanitize()` wrapper (DOMPurify) applied to every page's HTML before it's stored in state — the measurement clone still gets raw HTML (it's never rendered via `dangerouslySetInnerHTML`). Calls `checkDuplicateSlugs` once per pagination reset.
  - `src/types/book.ts`: added `slug: string` to `Chapter` (not `Book` — routing itself is a later milestone).
  - `src/data/book.ts`: added a `slug` to all 12 chapters (kebab-case of the existing `id`). Migrated chapters 5–10 (the poems) from raw 4-space alternating indentation to the `|` line-block marker, translating each line's leading-space count into the marker's indent. Added three temporary chapters — `test_formatting` (heading, bold/italic, `:::` fences, a poem line), `test_list` (30-item list), `test_blockquote` (25-line blockquote) — to give the required success-criteria coverage something concrete to render against, since none of the 12 original chapters use these constructs. Left in place for the planning session's manual review; flagged for a decision on whether to keep or strip before merge.
  - List/blockquote/line-block wrapper elements and headings needed explicit inline `style` (not Tailwind utility classes) for list markers, blockquote left-border, and heading weight/spacing, because Tailwind's preflight reset strips default `ul`/`ol`/`blockquote`/`h*` styling and these elements are injected via `dangerouslySetInnerHTML`/`innerHTML`, not JSX, so utility classes on them can't be relied on.
- **Verified**:
  - `npm run build` and `npx eslint .` both pass clean.
  - Manual browser walkthrough (via a temporary Playwright script, removed before finishing) of all 12 original chapters plus the 3 temporary test chapters, advancing page-by-page to the end of the book: no console errors or warnings, no raw markdown syntax leaking into rendered text, no malformed HTML.
  - Confirmed the poem chapters (`What Love is?` etc.) now visibly show the alternating-line indentation the `|` markers encode — see note under "What's left" about this being a visual **change**, not strict pixel-identity, versus the old behavior.
  - Confirmed, with a temporary 30-repetition bold/italic paragraph, that a paragraph genuinely splits mid-sentence across a page boundary with `<strong>`/`<em>` cleanly closed on the first page's fragment and reopened on the second's (captured the raw HTML at the boundary to verify tag balance directly, not just visually).
  - Confirmed the 30-item test list and 25-line test blockquote split across multiple pages at item/line boundaries — no item or line was ever truncated mid-text, and the list/blockquote as a whole was not forced to stay atomic.

Rewrote it stateless — a single pass over the whole chapter list per call — so it isn't order/invocation-count dependent. Caught via the manual browser walkthrough before this was reported as done, so no `MISTAKES.md` entry (nothing had landed as "finished" yet).
